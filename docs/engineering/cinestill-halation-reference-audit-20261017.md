# CineStill 光晕参考与实现差异 · 2026-10-17

本次按用户提供的 15 张成片参考，检查现有源码、模型元数据与本地固定版本 Fotufilm 配置。只做只读源码/资料核对，没有执行图像渲染、性能或其他测试，没有修改效果参数，也没有打包。

## 确认的事实

- `research/fotufilm/profiles/cinestill800t.json` 与 `cinestill400d.json` 的 `layeredTransport.constructionID` 分别为 `cinestill800t-parent-without-backing-v1`、`cinestill400d-parent-without-backing-v1`。当前素材没有选成带 remjet 防光晕背层的 Vision3。
- `MobileFilmRenderer.kt` 按两个独立 CineStill ID 选择专用分支；新配方默认开启 Halation，已有配方仍保留保存的开关。
- 当前 `tools/produce_fotufilm_models.py` 为 800T 人工指定返光 `[.12,.004,0]`、90µm，400D 为 `[.065,.003,0]`、65µm；native 使用 `.65/1.3/2.6` 三尺度和 `.25/.5/.25` 权重。这些是项目艺术近似，不能称为 Fotufilm 原生 CineStill 光晕或实测标定。
- 原始配置还包含独立 `halationProfile`、`halationReturnMatrix`、分层输运配置。固定版本的 `Halation.swift` 会拟合空间核、按接收层归一化返光矩阵；目前并未完整移植这些行为。不能通过比较一个 strength 数字判断两种实现的最终视觉强弱。
- native `prepare_spatial` 先将线性 RGB 作面积平均，CineStill 最长边上限 1024，然后才计算胶片曝光响应及模糊。面积平均保留区域均值/积分能量，却不保留单个小光源的峰值，且先平均后作非线性响应不等于先响应再平均。2400 万像素输入中小灯点可能因此被削弱，程度需要相同原图对照确认。
- 当前输入为已处理的 sRGB JPEG（RAW 也只提取内嵌 JPEG），没有拍摄时完整场景高光动态范围。被相机色调映射或裁剪的信息无法从 JPEG 精确恢复；移动端需要明确的显示图像高光近似，而不能假装恢复真实胶片曝光。

## 从参考图读取的目标

墙灯、餐厅灯、招牌字和扶梯灯管（附件 3、4、7、14）明确展示：明亮且清楚的灯芯，轮廓附近饱和红橙返光，向外快速衰减，暗部保持分离。不是全图增加红色、饱和度或雾化。附件 8、11、13 的可见光晕更克制；这些成片没有统一曝光、扫描/后期和对应数字原片，不能把所有图当作同一强度的定量标定。

## 后续修改的重点与证据边界

1. 核对同一原始 JPEG 的 Halation 开/关输出，分清用户安装版本、开关保存状态、输入高光和实际渲染问题。当前仅有目标参考，没有这一组输入/输出，不能判定主要损失环节或声称改善比例。
2. 先解决小光源提取与降采样：在高分辨率输入阶段估计高光贡献，再汇入有界空间场；需同时防止噪点、白墙和皮肤被当成发光源。峰值不能直接替代均值，否则亮点能量会被无条件放大。
3. 重新实现/适配返光核及通道传输，或者明确采用专门针对 JPEG 的 CineStill 外观。核半径、能量、灯芯保留与外沿红橙色需要一起校准，不能只把 strength 乘数放大。
4. 两款 CineStill 分别调校，400D 不应只按名称假定一定比 800T 弱；普通胶卷继续保留用户指定的 SpektraFilm 默认路线。
5. 保持移动端有界内存/空间计算与全尺寸输出，性能目标不变。没有执行对照或计时前，不声称效果达标或骁龙 865 耗时不变。

官方资料：[CineStill FAQ](https://cinestill.film/pages/frequently-asked-questions) 说明 remjet 的防光晕作用，及 CineStill 的无 remjet 特征；400D 从制造时便没有该层，不能简单描述成所有产品都对成品电影卷做后期除碳。此项是材料背景，不是本项目算法的效果证明。
