# 双 LUT 原型源码

2026-10-11。按用户最新要求优先进入影像编辑，当前是源码接入：没有编译、运行、解析样例执行、照片效果验证或性能测量，也没有 APK。

## 已接入的路径

本地 JPEG／RAW 内嵌 JPEG → 按方向解码至 sRGB 位图 → LUT 1 → LUT 2 → 可选颗粒 → 独立尺寸／质量的 JPEG 导出。

- 支持 .cube 的 1D、3D、1D shaper + 3D；红色索引最快，1D 线性、3D 三线性插值。尺寸限制为 1D 2～65536、3D 2～65。
- 支持 `DOMAIN_MIN/MAX` 或各阶段 `LUT_1D_INPUT_RANGE`／`LUT_3D_INPUT_RANGE`。同时声明两套不同范围的格式拒绝导入，避免模糊解释。实际预览与导出未运行确认。
- 槽 1、槽 2 各自强度 0～100%，顺序可交换，允许两个槽使用同款 LUT；0% 为原输入。两次插值混合完成后，在最终输出转换为 8 位 sRGB。
- 颗粒为按照片稳定身份、原图坐标生成的单色噪声，强度独立；预览与导出采用同一程序，但不同采样分辨率不保证逐像素相同。它不是光谱胶片颗粒模型。
- `.cube` 本地导入通过系统文件选择器读取，最大 32 MiB，严格 UTF-8、完整行数和有限数值检查。复制到应用私有 `files/lut-library/` 的原子二进制缓存，按输入文件 SHA-256 命名；原始文件不修改。UI 名称采用文件名，避免多份 Resolve LUT 都叫“Generated by Resolve”。暂不支持 .vlt。
- 每个处理批次共享两槽配方与颗粒，由 Room 5 新表 `batch_lut_recipes` 保存；4 → 5 仅新增表。内存草稿避免数据库反馈覆盖刚拖动的参数，250 ms 后保存，导出前再保存快照。保存失败有说明，不静默换用其他 LUT。
- 预览和导出共用 `LutRenderPlan`。既有原型主预览最长边 1280，参数停止变化 180 ms 后更新；图库卡片最长边 320，独立 PhotoProcessor 默认长边 960。后续新增原生 CPU 扫描行路径，直接处理位图、保持双槽插值和颗粒；原生库不可加载时使用原 Kotlin 32 行缓冲。效果预览加入 8 MiB／2 项 LRU，整批成片不使用小图缓存。完整输出仍需要位图内存，默认 100% 没有隐藏缩小；源码措施不等于手机性能或两实现数值一致已验证。见 手机处理优化。
- 工作台提供原图对比、清除效果、独立强度、交换顺序、颗粒和 .cube 导入。图库提供两列拍立得卡片、全部／内置／本地分类、名称搜索；点击进入全屏实际照片效果，再点“选择该 LUT”。当前卡片使用用户当前照片，不冒充创作者例图。

用户提供的 10 款内置文件与相机风格元数据见 资产记录。STD／NAT 提示来自文件注释；应用不自动判断原 JPEG 的照片风格，也不会猜测 V-Log 输入或给 JPEG 自动套 log 转换。

## 下一步

后续功能源码已经接入实际光谱胶片管线、统一曝光／Halation／三档黑柔，以及逐张／首张继承草稿；曝光和相纸曝光合并为一个参数。共享画框绘制与导出预览亦已接入，胶片和 LUT 使用同一 `BatchExportOptions`。这些功能没有编译或实际渲染证据，见 胶片接入、[画框功能](frame-export.md)。每批一次显影／反转动效和正式界面由另一个前端负责，调用边界见 [前端交接](frontend-contract.md)。

LUT 图库继续接入取色与组合筛选后端：实际当前照片单 LUT 卡片、Android Palette 颜色及明确来源、可保存题材、搜索／颜色家族／例图近黑白筛选。功能入口见 图库接口，尚未编译或运行，原型 UI 本轮不改。创作者真实例图的取得、官方正常目录／下载访问、VLT 兼容、GPU 与大图内存改善继续待办。CPU LUT 路径不能作为完整参考胶片管线完成的证据。
