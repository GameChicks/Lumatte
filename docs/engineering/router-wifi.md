# 同路由器连接（STA）

2026-10-11：已接入普通浏览／下载、相机请求的拍后／选定发送、后续接收及显式发送更新的 STA 源码和工作台入口。未编译、运行、测试或打包；不能据此宣称任何相机型号已兼容。

## 使用范围

手机先通过系统设置连接路由器；相机也需要事先保存该网络及密码。用户读取蓝牙相机资料后，可输入路由器名称并点击“让相机连接此路由器”浏览／下载；具备发送通知能力的相机另有“通过此路由器等待相机发送”。应用只发送名称，不读取、保存或配置路由器密码，不更改手机的系统 Wi-Fi 配置。直连入口仍独立保留。

当前需要系统提供至少一个已有 Wi-Fi Network；只有一个时使用它，多个时在蓝牙操作之前显示明确的选择列表。列表使用本机 IPv4 地址及系统默认标记帮助区分，不读取 SSID，不自动选默认网络；可刷新或取消。选择后再次核对 Network 在线，再注册断线观察并检查网络。Network 在启动前固定下来，发现和相机 HTTP 都绑定该 Network；蜂窝网络、VPN、默认网络切换及另一个 Wi-Fi 不作为自动后备。取消选择不启动本次蓝牙连接。普通查找及重连也使用相同选择／绑定路径，见 [已有网络选择](wifi-network-selection.md)。

同一 Network 上已有应用 Wi-Fi 请求时保留该请求，不先关闭再将它当成系统连接观察，以免释放请求导致刚选中的网络消失。不同 Network 则建立新的应用观察后释放旧引用；仅操作本应用请求／观察，不配置或主动断开系统已有的路由器网络。

输入的名称由用户核对，并非从 Android 读取的 SSID。为避免为名称读取增加定位权限，本轮未接入系统 SSID 读取，也不声称已证明输入名称与当前 Network 相同。错误名称、相机未保存密码、路由器设备隔离仍可能导致失败。名称仅保存在当前界面／连接操作内存，不写 Room、DataStore 或日志。

## 恢复的协议依据

依据只读官方 LUMIX Sync 2.0.15 APK 的 JADX 输出，原始 APK 和恢复源码未修改。

| 环节 | 恢复位置 |
|---|---|
| 路由器名称写入 Wi-Fi 服务 `5ae57260-3214-11e6-979e-0002a5d5c51b` 的 `18345be0-3217-11e6-b56c-0002a5d5c51b` | `p033E4/C0393g.java:m1791q1`，写入类型 12 |
| SSID 去外层引号后补 NUL 至 32 个字符，再 getBytes | `p321v4/C5119d.java:m27962a`、`p068J4/C0941p.java:m4403x` |
| 名称写入后等待选择通知；`18345be1...` 首字节 0 为 STA，其余为 SoftAP | `C0393g.java:465–530`、其内部 `e.a.run` |
| STA 向 `0d6f1880...` 写固定 2 | 同通知处理与 `p026D4/C0272a.java:f1074i` |
| 类型写入成功后普通连接向 `e182ec40...` 写固定 3 | `C0393g.java:1005–1013`、`C0272a.f1069d` |

先在连接操作前解析字面名称，检查非空、无控制字符、完整 UTF-8 且编码后至多 32 字节；不截断、trim、大小写转换或 Unicode 规范化。工作台显示字节计数与输入错误，普通／发送／更新三个入口使用同一个 `CameraRouterSsid`。按原有旧／APS 分支建立应用自己的身份，暂时读取的相机直连密码立即释放。检查名称写入、类型写入、模式写入及两种连接通知能力；缺少任何一项就提示手动入口。

名称写入沿用参考的字符补齐规则：在原始 UTF-8 字节后补 `32 - String.length` 个 NUL，其中 `String.length` 为 UTF-16 单元数。[Android Charset 文档](https://developer.android.com/reference/java/nio/charset/Charset#defaultCharset()) 确认平台默认字符集为 UTF-8，因而参考代码的 `getBytes()` 可明确还原为此编码。ASCII 载荷仍为 32 字节；多字节名称载荷更长。这里的 32 字节限制针对实际 SSID，不含协议补零；不能把整个 BLE 载荷固定截成 32 字节。

参考代码去掉从系统获得的 SSID 包装引号；本应用输入来自用户，按字面保留引号，避免更改名称本身含引号的网络。不是要求用户额外加一对引号。相机返回的 SSID 也使用严格 UTF-8 解码，到首个 NUL；非 UTF-8、截断字符和控制字符提示手动入口，不用替换字符连接到另一个名称。

名称载荷长于默认 ATT 单次写入容量，因此先请求至少 MTU 64，等待 `onMtuChanged` 成功且实际 MTU 至少为本次载荷长度加 3，随后才订阅与写入。实际 MTU 以回调为准；[Android BluetoothGatt 文档](https://developer.android.com/reference/android/bluetooth/BluetoothGatt#requestMtu(int)) 说明 Android 14 起首个客户端会请求 517，不可把请求值当作实际协商值。此处不要求恰好 64，不截断名称。举例：`摄影WiFi` 为 10 个 UTF-8 字节、6 个 UTF-16 单元，补 26 个 NUL 后载荷为 36 字节，需实际 MTU 至少 39；这是源码规则说明，未执行验证。

订阅完成后开启本次名称回复等待，写名称并等待 GATT 成功回调及 STA 通知，两者缺一不可；20 秒未确认或选择 SoftAP 即结束，不自动切换直连。随后顺序写类型 2、普通模式 3，分别等待 GATT 回调。连接拒绝、空状态、取消、蓝牙断开结束 STA 交接。

GATT 的写成功及 STA 选择只说明协议步骤完成。继续在固定 Network 上发现相机；普通入口使用 SSDP，发送入口具备能力并收到就绪时先读取相机返回的地址，在同一地址上定点发现，见 [连接地址](camera-connection-address.md)。有界等待未找到时提示核对名称、相机密码及路由器互访。多个相机必须由用户选择；普通入口只接受 BROWSING，发送入口只接受相机请求的 HTTP 模式，握手检查发生在目录初始化之前，不接受意外模式。BLE 地址与发现的 HTTP UDN 之间没有恢复出的密码学绑定，不把单个发现结果称作已证明是同一台相机。

## STA 发送、后续接收与更新

发送入口先重新读取蓝牙身份和连接资料，检查 STA 写入与两种发送通知能力。相机直连密码在等待之前释放，只将相机返回的 SSID／能力元数据用于本次关联；路由器名称仍来自用户输入，二者分别保存，不互相替代。

与直连发送一样订阅四种通知，等相机模式事件 1／4（最长 90 秒）。收到事件后才写路由器名称，等待 STA 回复，再写固定 Wi-Fi 类型 2 与对应连接模式 1／6，各写入等待 GATT 成功回调。等待名称回复期间的发送停止、模式变化、资料更新与断线均结束本轮，不能被已就绪的 STA 回复覆盖。模式数字仍只从已识别事件产生，用户不能任意指定。

发送 STA 分支依据为 `C0393g.onCharacteristicChanged` 样本行 639–695：模式事件设置 1／6 后，根据手机已有 Wi-Fi 走名称类型 12 写入；行 465–484 的发送选择回复写类型 2；行 886–921 的类型写回调后台分支继续写当前 1／6。应用采用用户显式启动和固定顺序，不复制参考应用的系统开关、前后台私有偏好或完整遥控通知组。

发送发现、选择与 HTTP 握手保留预期模式；成功后仍由用户发起单轮或后续接收，不在连接按钮中自动保存文件。后续接收使用现有前台服务、Room 同批次记录及 BLE 通知，不新增接收器或相机确认策略。重新订阅时沿用相机返回 SSID 的变化检查；其 STA 下逐机型语义仍未以设备验证，变化或不支持会停止接收，不能用用户输入的路由器名称绕过该检查。

模式变化或已知模式的资料更新暂停旧批次后，进程内更新请求另保留路由器名称。用户点击更新时继续 STA 路径，重新读取资料、获取当前已有 Wi-Fi Network、重做 STA 选择和固定发送模式，按原相机 UDN 筛选发现结果并核对 HTTP 模式。旧队列、UNKNOWN 确认和按模式保存的批次规则保持不变。失败／取消保留更新入口及原路由器路径，不静默改用 SoftAP。名称是进程内输入，不读取旧密码，进程退出后需重新连接；用户更换路由器时可通过新的连接入口重新输入，旧记录仍保留。

多个相机等待用户选择的情况下，启动 GATT 随发现操作返回关闭；后续选择仍核对保存的 HTTP 模式，不能声称所有相机都已完成握手。更新期间尚未发现原相机则不会把旧接收绑定到其他 UDN。

## 尚需继续

- STA 更多连接资料通知、扩展事件、BLE 与 HTTP 身份对应、相机返回 SSID 的逐机型语义及网络改变后的交接差异。
- 多字节 SSID 的逐机型实证、非 UTF-8 原始 SSID、多个 Wi-Fi Network 的系统可见性／生命周期差异、低 MTU 设备的完整写入方式、逐型号系统绑定和固件差异。中文等完整 UTF-8 名称已有源码路径，不等于各型号已接受较长的字符补齐载荷；网络选择源码不证明厂商系统已同时暴露多个可用网络。
- AP 隔离、组播被禁用时的逐型号差异。发送分支已接入可选地址读取；普通浏览仍使用 SSDP。现有 SSDP 发现仍有直接网关后备，普通路由器网关不是相机，不能把该后备当作 STA 发现保障。
- 用户明确要求后才进行编译、实际设备连接与相关测试，按实际结果更新逐型号表。
