# CineStill JPEG 光晕修正 · 2026-10-17

0.2.1 的 Fotufilm 默认物理核已通过数值对照，但在 JPEG 输入上红晕仍很弱。维护者提供的灯箱、夜街和车内照片再次复现了这个问题。此前“物理计算移植正确”不能作为观感问题已经解决的依据。

## 修改

保留 Fotufilm 原核、跨层返光矩阵与三阶段模型资产，在两款 CineStill 的扫描结果后加入独立的 JPEG 高亮晕边。普通胶卷仍进入原有 SpektraFilm 路径；关闭光晕时，两部分都跳过。

这是一项针对 JPEG 的外观近似，不是上游默认物理模型的新参数，也不声称从 JPEG 恢复了真实场景辐射亮度。Fotufilm 的原始记录见 [物理核移植](fotufilm-physical-halation-20261017.md)。

- 先解码线性 RGB，在面积缩小之前提取高亮。以 `max(R, 0.85G, 0.65B) × 曝光增益` 作为触发量，0.55–0.95 之间平滑进入，纯蓝光贡献较少。
- 空间分析仍限制长边 1536；三个近似高斯分量使用 0.10 / 0.18 / 0.28mm，按短边对应 24mm 缩放。权重 0.25 / 0.65 / 0.10，让主要晕边有可见厚度，远端尾部只占少量。
- 在扫描结果的线性光空间加入红橙分量，减掉当前像素的直接高亮，保护灯芯及均匀亮面。800T 强度 1.4，400D 为 1.0，和现有光晕开关联动。
- CPU 与 GLES 计算相同。Kotlin/JNI 控制数组由 59 扩为 60 个浮点数，末项是此强度；普通胶卷必须为 0。旧验证夹具仍可用 59 项复现原物理效果。
- 不新增边框、水印或内容识别。应用自己的画框仍在胶片处理后添加。

## 观感迭代依据

第一轮的大范围低强度尾部像有色柔光；第二轮收窄过度，变成细红线。维护者指出两者都不符合参考。最后重新查看壁灯、餐厅吊灯与招牌的实拍参考，将能量集中在更宽的主体晕边，并保留短而柔和的外缘。

在同一 1000×1000 白灯块测试中，上一轮细线的红色半高宽是 2px，本轮为 8px。这个数字只用于约束本次形状，不是所有照片的固定晕边宽度。最终还查看了整图和灯箱局部，避免只凭差分最大值判断效果。

共 17 项定向断言通过。实拍参考本身含有处理和压缩，不是实验室胶片测量。原有 LFM 导出图缺少完整配方，因此没有声称逐项复现维护者当时的参数。

两张已带纸框的参考仅在验证夹具中手动裁出照片区域：街景 `(230,68,1210,1373)`，车内 `(66,231,1373,1208)`。产品算法没有自动裁剪或纸框判断。用户照片及生成样图不提交到 Git；本地可查看附件在 `dist/review-20261017/`。

末轮两 ABI 原生库和 app Kotlin 的编译结果以本地 `source-compile.log` 为准。已按用户授权生成并安装 0.2.2 调试 APK，包含本轮新算法。签名、ZIP／ELF 对齐与哈希记录保存在 dist；不以模拟器结果替代实体相机或手机验收。
