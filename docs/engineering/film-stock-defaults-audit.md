# Gold 200 / Ultramax 默认色彩与光晕参数核对

用户报告负片颜色偏浓，尤其是 Gold 200 和 Ultramax。尚未收到光晕关闭后是否依旧偏浓、输入样片、对应输出及安装包版本，因此不能确认手机上的实际算法版本或把整个色彩问题归因于 Halation。

## 已核对的源码与资产

- 20 个现有彩色模型的生产快照：相机曝光 0 EV、相纸曝光倍率 1、自动曝光关闭；印相曝光补偿关闭。运行时用户曝光只乘到胶片线性响应一次，没有重复乘到相纸。
- Kodak 负片使用 `kodak_portra_endura` 印相表；电影卷使用 `kodak_2383`；富士负片使用 `fujifilm_crystal_archive_typeii`。不是把所有胶卷强制套到最高反差相纸。
- 没有新增全局饱和度/对比度加成。显影中的 DIR 是上游默认局部化学参数，已烘入一次；空间 DIR 省略。仍然可能存在固定印相选择、输入相机 JPEG 风格、查表近似或默认化学参数造成的观感差异，不能据此宣称色彩已经准确。
- JPEG 明确解码为 sRGB；response 表接收编码 sRGB，输出线性胶片响应，development 接收 log10 曝光，scan 表输出编码 sRGB。扫描输出没有在手机端再重复做一次 sRGB 编码。表格轴顺序与 CPU/GLES 索引均为第一通道最快。

## 确认存在的艺术参数

上一版 `lfm-optical-spatial-v2` 默认对所有彩色负片/电影卷采用 `RED_LAYER_RETURN`，把返光改为红记录、少量绿记录和零蓝记录；原生层还给所有返光再乘 2。该方案用于追求用户提供的红晕观感，但没有逐卷标定，把这种艺术外观作为普通胶卷默认并不稳妥。

Gold 200 与 Ultramax 的资产原始返光为 `[0.08, 0.02, 0]`，上一版普通入口变成有效 `[0.16, 0.0064, 0]`。红记录的混合份额从原始 `0.08/1.08 ≈ 7.4%` 提高到 `0.16/1.16 ≈ 13.8%`，并且通道比例更红。Portra 等模型的原始红记录返光约 0.015，因此前两卷更容易显现这种改动。这里的百分比是返光混合份额，不是饱和度或视觉误差百分比，也不能证明关闭光晕后的底色问题。

## 当前修改

版本改为 `lfm-optical-spatial-v2.1-stock-defaults`。普通 `FilmSpatialOptions()` 恢复 `STOCK_RETURN`，使用每卷原模型的 RGB 返光比例与 1 倍强度；原生层不再隐含乘 2。黑白与反转片也恢复单位返光增益。

`RED_LAYER_RETURN` 保留为显式后端艺术选项，彩色负片/电影卷的红暖比例和 2 倍增益在 Kotlin 计划解析时一次性确定，原生 CPU/GLES 不再重复增加增益。没有把它冒充真实 CineStill 800T，也没有新增专业参数 UI。现有配方的曝光、黑柔与 Halation 开关保持原值；没有迁移旧数据库或批量关闭用户的开关。

三阶段色彩表没有重新生成，基础色彩没有统一降饱和度；空间网格、GPU 加速、最终导出尺寸和压缩质量设置保持现有路径。新导出日志记录胶卷 ID、相纸 ID、EV 和实际 Halation 外观，方便核对运行版本与参数。

## 待确认

先确认同一 Gold 200 / Ultramax 输入在 Halation 关闭、0 EV 时的观感与当前包版本。若仍偏浓，需要比较基础响应、局部 DIR 与印相模型、输入相机照片风格及查表近似；不能靠全局褪色宣布模型修复。用户之前的关/开光晕参考只规定空间外观，不能作为普通日常负片的统一调色标定。

本轮只核对源码/资产并修改默认返光，未渲染照片、未进行设备或其他测试，未生成 APK/AAB。修改前基线为 `967249c`；NDK arm64-v8a / x86_64 原生库及 `:core:media:compileDebugKotlin`、`:app:compileDebugKotlin` 编译通过。恢复上游默认只提供较保守的基线，不代表已通过实拍色彩校准。
