# 发送连接返回的相机地址

## 参考依据

官方 LUMIX Sync 2.0.15 的 JADX 源码中，发送模式在连接状态通知 `e182ec41...` 首字节为 0 时读取类型 15。`C0393g.m1762R0(15)` 将它映射到发送服务 `6b005f20-3214-11e6-a5ac-0002a5d5c51b` 的 `e1392720-3215-11e6-a035-0002a5d5c51b`。

`C0393g.onCharacteristicRead`（样本行 739–745）将该特征的原始值通过 `C0941p.m4391r` 转为 UTF-8，交给 `ImageAppTotalService.m17289s0`。该字段由 `m17253O` 返回，并在 `RunnableC3468f` 创建 HTTP 客户端时 Java trim；`RunnableC5294a` 构造器将它拼入 `http://%s`，设备描述位于 `:60606/Lumix/Server0/ddd`。它由参考软件用作相机地址，依据不是特征名称猜测。没有读取参考应用的持久配对地址。

## 接入顺序

SoftAP／STA 的发送启动与发送更新均采用此补充路径，普通浏览入口保持原有发现方式。

1. 完成本次蓝牙身份与连接订阅，取得相机请求的固定发送模式 1／6；Wi-Fi 类型仍按用户选择的直连／路由器流程写入。
2. 在发送模式写入前开启本次就绪等待，模式写入必须收到 GATT 成功回调。仅接受此后当前 GATT 的连接状态 0；订阅时的提前状态不作为本次地址读取依据。
3. 特征不存在或不具备 READ 属性时直接跳过。具备能力时等待最多 8 秒；未得到状态 0 仍按既有 SSDP 流程发现。这是原型的有界补充等待，不表示所有型号都应在 8 秒内返回。
4. 得到状态 0 后串行读取地址特征，仍使用现有每次 GATT 请求的 20 秒等待。停止、模式变化、资料更新、蓝牙断开和外部取消可以终止等待；停止信号不会被成功状态覆盖。
5. 成功读取的字节上限 64，UTF-8 格式按 Java trim 去掉首尾 NUL／空白，只接受规范十进制 IPv4、私有／链路本地范围。公开地址、主机名、URL、端口后缀、IPv6、前导零和其他格式不转为另一猜测地址；读取失败或非法格式结束本轮交接，用户可使用手动入口。

`CameraConnectionAddress` 只能由核心模块创建，地址仍经正常范围检查；它不是 UDN、密码或相机身份认证凭证。返回字节读取后清零，地址只在本次握手和发现中使用，不持久化或跨重连复用。尚未恢复的多字段或其他地址格式不能据此宣称支持。

## 定点发现

有效地址通过 `CameraDiscovery.discoverAt` 在所选 Network 上读取固定设备描述，不发送组播、不扫描子网、不先访问路由器网关。仍检查设备描述中的 Panasonic 制造商与相机字段，并要求 ContentDirectory 地址属于同一主机；然后执行应用正常 HTTP 身份握手及预期发送模式检查。使用完描述请求关闭它的临时 HTTP 客户端。

交接允许在同一地址上有界重试（协程等待上限 45 秒，单次阻塞 I/O 还受现有连接／读取超时约束）。有相机返回地址后，不因为该地址暂未响应、描述不合要求或原 UDN 不匹配而降级为其他发现的相机。更新时继续按原 UDN 核对；缺少 UDN 时沿用相同描述地址／型号规则。错误或不响应的地址不会将旧接收队列绑定到另一台相机。

这个路径能在组播被抑制而单播互访仍可用的网络中提供定位方式，不绕过路由器 AP 隔离，也不能证明 BLE 和 HTTP 间存在密码学身份绑定。当前没有设备证据，不能称为组播受限场景已验证通过。

## 尚需继续

- 普通浏览是否有同样的就绪／地址读取步骤：本样本只定位到发送分支，未把它擅自扩展到普通浏览。
- 地址通知的逐型号时序、缺少就绪时的后续地址读取、IPv6／扩展格式、BLE 与 HTTP 身份对应。
- 相机地址变化后的其他事件及兼容行为。更新连接会重新获取地址，旧地址不是恢复依据。
- 用户明确要求后才进行编译、连接设备和相关验证。
