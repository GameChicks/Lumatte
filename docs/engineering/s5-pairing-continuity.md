# S5 配对交接与连接入口

> 2026-10-14 补充：用户提供第三方 S5 成功连接日志，确认首次配对模式 5 与重连模式 3 的区别；同时修正系统确认页面造成的后台取消及过短 Wi-Fi 等待。详见 [日志核对与源码修正](s5-success-log-pairing.md)。以下保留 2026-10-13 的历史说明；普通直连如今不再无条件写模式 3。

2026-10-13 用户新反馈：现已能发现 S5、触发相机配对，但相机屏幕每次显示“配对失败”。手机仍为 vivo X50 Pro+ / Android 13。发现成功是用户反馈，尚无配对/浏览/传输成功证据。

## 已核实的差异与本轮修改

- 初次选择相机此前只读取 Wi-Fi 资料，随后 `withConnection` 的 finally 立即关闭 GATT，用户再点另一按钮才重新连接并启动 Wi-Fi。改成明确的“配对并连接所选相机”动作：停止扫描 → 单个 GATT 会话登记/读资料 → 固定普通传输启动 → 系统 Wi-Fi 请求 → HTTP 相机确认/浏览。原 GATT 在交接完成、失败或取消后才关闭。此时序问题是源码证据，是否为这台相机失败的原因仍待确认。
- 参照恢复的官方 `C0393g.onServicesDiscovered`/`m1763T0`，在身份写入前串行注册本项目所用的连接状态及 Wi-Fi 选择通知，等待描述符写入回调。会话内记录已订阅项，后续启动不重复写入相同描述符。只订阅连接用途，不移植官方控制/拍摄相关通知。
- 官方旧身份流程为标识 → 名称 → SSID → challenge → password；调整旧分支读序。APS 仍为 challenge → 编码标识 → 编码名称 → SSID → password。来源为 `C0393g` 的服务发现、写入与读取回调以及 `C5117b`。
- 每次 GATT 失败/超时在用户界面给出具体操作与状态，原始操作类型/UUID/状态写入 `LFMBle` 日志；不记录密码、challenge、身份字节、广播内容或设备地址。

## 排除的错误推断

此前进度消息曾把手机标识推断成普通随机 UUID；进一步核对后发现 `LumixCameraSession.newClientId()` 从基础实现提交 `834cca9` 起即带 `4D454930-0100-1000-8001-` 前缀，BLE 的 16 字节表示与参考生成规则一致。本轮**没有修改身份或迁移配对数据**，也不能把该推断列为修复原因。

## 连接界面

扫描结果改为相机选择卡片及单选控件，显式点击“配对并连接所选相机”，先申请该动作需要的蓝牙/Wi-Fi 权限再交接。列表中的广播 pairing 仅标注“相机正在等待配对”，不当作已经成功。

连接显示所选相机、四阶段路线和不定进度条；等待与驱动调用耗时未知，不伪造百分比。“停止查找”“取消连接”“暂停传输”依操作区分。保留手动 Wi-Fi；对于 normal 广播的相机，另留“已完成配对 · 查看其他连接方式”高级入口，用户明确读取资料后选择原有路由器/发送方式。normal 广播不是与本应用已配对的证明，该入口不宣称完成新配对，首次仍使用主按钮。

主页设置入口使用现有 `RoundAction`、圆形点阵/线条设置图标及同一 `frostedBackdrop` 像素取样；尊重明暗主题和减弱动画。没有重做全站前端。

## 验证边界

本轮仅进行源码编译，不执行测试或设备验证、不打包。相机显示的配对失败尚不能据此标记为已修复；下一次经用户授权交付后需要观察完整交接结果与具体失败步骤。普通连接仅写固定传输 Wi-Fi 类型 1、连接模式 3，不增加系统 createBond、遥控或远程电源操作。
