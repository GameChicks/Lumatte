# RAW import and 10-bit working cache

The pinned LibRaw source remains unchanged. Default `nativeExtract` retains the JPEG-only thumbnail path. Explicit file-import `nativeDecode` performs sensor unpack/demosaic, camera white balance, no auto-brightening, `output_color=4` (LibRaw ProPhoto D65), `output_bps=16`, linear gamma. Balanced uses half-size/bilinear; full size uses AHD. No optional SDK/OpenMP is enabled.

Linear 16-bit output is immediately encoded with an sRGB-like transfer and rounded to 10 bits per wide-gamut channel, packed RGB10 in a 32-bit word. The 24-byte little-endian header is `LFM10RGB`, width, height, version 1, gamut 4, followed by exactly width*height words. `native/common/raw10.hpp` validates dimensions/version/length and maps read-only without a full-image float copy. A 1024-entry inverse-transfer table, linear-light interpolation, the inverse pinned LibRaw colour-basis matrix, and source adjustments feed model/LUT lookups as floats. Source EXIF orientation is applied exactly once in coordinate mapping. It is LibRaw ProPhoto D65, not an ICC ProPhoto D50 file.

`working.raw10` is the processing source. `source.jpg` retains the legacy private path but contains an 8-bit PNG used for display and output allocation; all raw original/film/LUT processing explicitly reads RAW10 rather than using PNG samples. The source RAW bytes remain in `original.raw`. Optional `rawDecoded` in source manifests supports recovery, and the database schema is unchanged. Exports re-encode normally and read EXIF from retained RAW when available. Ordinary JPEG/PNG export is still 8-bit; no 10-bit HEIF or 16-bit RAW-editor claim is made.

RAW film rendering currently uses native CPU to avoid the existing 8-bit GPU input upload; JPEG keeps GLES with its existing fallback. Input is capped at 80 MP sensor storage, output at 60 MP, and LibRaw raw memory at 512 MiB. Full-size import checks for at least 1 GiB available system memory; these are guardrails, not a peak working-set guarantee. Cancellation is polled by the native callback/rows. Failures never silently substitute the 8-bit display copy or embedded JPEG.

At the maintainer's explicit request, targeted checks passed: 17 native RAW10/source-adjustment checks (including all eight EXIF mappings and a 14-bit synthetic ramp), four LibRaw sensor integration checks (synthetic Bayer DNG full/balanced, cancellation, invalid input), and actual JNI import plus original/film/identity-LUT rendering in an isolated Android emulator. No broad suite or benchmark was run. These synthetic checks do not establish S5 RW2 colour accuracy, physical-phone compatibility, peak memory or elapsed time.
