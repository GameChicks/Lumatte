# Lumix Film Mirror 安卓项目规划

## 1. 已确定的目标与边界

开发一个免费开源的安卓应用，将松下相机连接与传输、胶片模拟、双 LUT 处理和画框水印整合到同一工作流。支持 **Android 11 起的 64 位设备**，全部 Sync 支持机型纳入适配范围，先完成传输与成片，再补齐其他相机功能。

已经确认的参考 APK：

| 软件 | 提供的版本 | 参考用途 |
|---|---:|---|
| LUMIX Sync | 2.0.15 | 相机连接、传输和控制协议 |
| LUMIX Lab | 3.1.0 | 官方 LUT 目录、示例图和下载流程 |
| Film Companion | 0.3.7 | 暗盒、卷标、字体、动画及全部画框样式 |

项目目录目前为空，按新项目建立 Git 仓库。旧项目资料只作为资源定位线索，恢复结果以本次 APK 为准。

**RAW 只提取内嵌 JPEG。** 不进行传感器数据解码、去马赛克或 RAW 显影；编辑页和导出页显示小字：

> 使用 RAW 内嵌 JPEG · 1920 × 1280 · 输出尺寸以预览图为准

尺寸使用实际读取结果；说明默认只出现在界面中，不印入照片。没有可用内嵌 JPEG 时提示改用 JPEG，不自动启动 RAW 显影。

## 2. 技术架构与核心能力

### 安卓与影像处理

采用 **Kotlin、Jetpack Compose、Coroutines／Flow、Room、DataStore、NDK／C++20 和 Vulkan**。Compose 负责界面和动效，原生引擎负责照片计算；Vulkan 不可用时使用保持相同处理阶段的 CPU 实现。

胶片引擎以 [spektrafilm](https://github.com/andreavolpato/spektrafilm) 为模型基准，参考 [SpektraLab](https://github.com/JamesQiu2005/SpektraLab) 的原生实现移植。已有桌面 Vulkan 实现可供参考，但不能据此宣称安卓性能或算法一致性已经验证。[现有验证范围](https://github.com/JamesQiu2005/SpektraLab/blob/main/engine/WINDOWS_FEATURE_COVERAGE.md)

| 参考项目 | 本项目采用方式 |
|---|---|
| spektrafilm | 胶片光谱、曝光密度曲线、染料耦合、颗粒、halation 与印相／扫描模型 |
| SpektraLab | C++ 引擎组织、Vulkan 计算、分块处理和中间结果缓存 |
| filmify | 手机内存管理、显影展示和柔光处理思路 |
| Phos、Phos_refactor | 光学效果与参数交互参考 |
| Lut2Photo | 双 LUT 顺序处理、独立强度、颗粒和输出设置参考 |

保留模型的处理阶段；可缓存或预计算固定映射，胶片模拟不压缩成单个风格 LUT。Halation 使用上游已有模型，新增可独立调整的镜头柔光，避免重复叠加同一种散射效果。

JPEG 按其色彩信息解码到浮点工作空间后处理，最终转换到 sRGB 输出。界面不提供 RAW 专属的高光恢复或原始白平衡承诺。首批预设覆盖负片、电影卷、反转片、黑白卷，以固定上游版本实际提供的模型为准，包含 Gold 200。

RAW 预览提取通过 LibRaw 的缩略图接口实现，只开放文件识别与预览读取接口。[LibRaw 文档](https://www.libraw.org/docs/API-datastruct.html)

性能策略统一采用：

- 拖动参数时使用低尺寸预览，停止后更新清晰预览；过期计算结果不覆盖新参数。
- 预览和导出共用配方与处理顺序，颗粒种子随照片保存，避免反复预览时随机变化。
- 每次执行一张完整照片任务，大图采用带边界扩展的分块处理；动画独立运行。
- GPU 失败时回退 CPU，保持选定算法与导出尺寸，并明确显示处理状态。

### 相机连接与 Sync 功能

“与 Sync 同源”落实为**兼容同一相机协议和工作流程**，在本项目中独立实现。分析官方 APK 的协议、命令和状态机，建立 Kotlin 适配层。

已发现的 Sync 协议线索包括 BLE、`cam.cgi` 和 DLNA／ContentDirectory。后续按机型与固件版本整理握手、浏览、文件传输、事件通知及控制流程。

最终功能矩阵包含：

- 配对、连接、重连、相机发现和连接引导。
- 相机媒体浏览、原图与视频传输、多选、自动传输和传输设置。
- 实时取景、拍照、录像启停、曝光、白平衡、对焦及机型支持的其他控制。
- 电源操作、时间同步、定位记录、同型号设置复制。
- 官方固件下载、校验和升级会话，作为后期独立模块。

全部机型并行建立能力表；共同协议集中实现，型号差异进入适配配置。范围包含官方说明中的完整支持机型，以及 GH5、GH5S、G9 的有限功能支持。[官方支持说明](https://av.jpn.support.panasonic.com/support/global/cs/soft/lumix_sync/en/index.html)

能力表分别记录“已实现”“已真机确认”“待适配”“机型不支持”。提供的 APK 是协议样本，另外核对现行官方说明与新版固件差异。

相机连接使用的局域网客户端与官方 LUT 下载客户端分开路由，避免连接相机 Wi-Fi 后将互联网请求发往相机网络。[Android 网络请求说明](https://developer.android.com/develop/connectivity/wifi/wifi-bootstrap)

### LUT 目录与处理

已找到官方 `lutapi/v2/`、创作者、分类、列表和下载接口线索；匿名 GET 返回 400，当前尚未确认正常访问所需条件。

按你确定的顺序实施：

1. 研究正常访问路径，确认目录、详情、示例图和文件下载。
2. 能正常访问时，由手机直接请求官方服务，不自建服务器。
3. 无法直连时，支持 Lumix Lab 分享到本应用，以及本地 `.cube`、`.vlt` 文件导入。

官方目录接入封装成独立数据源，服务变化不影响已下载 LUT 和本地编辑。

内置五款自制基础 LUT：标准通透、暖调日常、冷调街头、电影青橙、黑白。官方创作者 LUT 按需下载，保存作者和适用 Photo Style 等信息；未确认再分发许可的官方文件不放入安装包。

双 LUT 按 **LUT 1 → LUT 2** 顺序处理，各自具有 0–100% 强度；支持交换顺序、颗粒设置、输出尺寸和 JPEG 质量。保留 LUT 的输入色彩空间信息，允许第一槽使用转换 LUT。[Lut2Photo 工作流参考](https://github.com/qh7574/Lut2Photo-Android)

示例图用 Android Palette 提取代表颜色，标注为“例图色彩”，结合分类辅助筛选。[Palette 文档](https://developer.android.com/develop/ui/views/graphics/palette-colors)

列表分页加载，示例图缩略缓存默认上限 150 MB；主动下载的 LUT 单独保存，缓存清理不删除它们。

## 3. 工作流、批量规则与统一设计

### 胶片模拟

**导入 → 选卷 → 参数预览 → 显影 → 反相／揭晓 → 画框与导出**

分类卡片保留你描述的构图：大标题与右侧暗盒。分类进入焦点并停止滚动后，文字缩到左上，暗盒展开，连续过渡到全屏滚轮。

全屏中：

- 上下滑动切换胶卷，保留惯性并吸附到中心。
- 中心暗盒明亮，上下暗盒变暗；跨过选中位置时触发一次轻触感反馈。
- 吸附停止、手指离开后等待 **400 ms**，再展开介绍页；新操作取消等待。
- “选择此卷”进入参数预览。
- 返回介绍页时保留位置，等待用户再次滚动后才重新触发自动介绍。
- 返回分类卡片后切换其他分类，展开与收拢使用同一组共享元素保持动画连贯。
- 状态栏和导航栏采用沉浸式呈现，返回按钮避开系统安全区域，不抢占边缘返回手势。

暗盒使用旧 APK 的底图、卷标和材质，配合分层透视、位移、遮挡和光照实现立体感。

反相参考视频制作**从下向上显现正片**的效果。展示动画与照片计算分开；反转片按其正片模型处理，揭晓动画不改变最终图像数据。

### LUT 选择

使用拍立得式卡片画廊，展示创作者例图、LUT 名称、作者、色卡和下载状态。底部分类条提供全部、日常、自然、街头、人像、电影、黑白，并提供搜索与颜色筛选。

点击卡片进入全屏例图页；已下载时显示“选择该 LUT”，未下载时显示“下载并选择”。下载完成后可切换到用户照片预览效果；编辑页提供添加第二个 LUT 的入口。

### 批量操作

胶片参数页提供两个明确模式：

| 模式 | 参数应用规则 |
|---|---|
| 逐张调整 | 每张照片保存独立胶卷与参数，可通过底部缩略图切换 |
| 以首张为准 | 当前批次第一张作为参数来源，后续照片统一使用其胶卷、halation、柔光、颗粒等设置 |

切换模式保留已编辑内容；开始处理时保存当前模式和配方快照。LUT 批量编辑沿用同一模式选择。

**画框只在导出阶段选择。** 一批照片统一使用同一画框预设及设置；布局按每张照片的比例适配。恢复旧 APK 的全部画框样式、字体、装饰和文字选项，建立样式清单与统一渲染器，供两条工作流共用。

每批只播放一次显影开场和一次代表照片揭晓，可随时跳过。其余照片显示真实进度与完成缩略图；查看结果不自动重播动画。逐张调整模式也遵守每批一次的动画规则。

任务支持暂停、取消和恢复；单张失败不丢弃已完成结果。源文件保持只读，导出写入独立文件。

### 设计规范

统一采用深色摄影工作台：石墨黑背景、暖白文字、琥珀色主操作、相纸色卡片。Palette 颜色只用于 LUT 卡片与色卡。

采用 8 dp 间距体系、16／24 dp 圆角、至少 48 dp 点击区域；正文使用系统无衬线字体，编号与参数使用等宽样式，水印字体沿用旧项目。

统一交互动效时长：普通反馈 180 ms、页面切换 300 ms、暗盒展开／收拢 450 ms。系统减少动态效果开启时简化旋转和惯性，保留清晰的状态变化。

## 4. 项目组织、接口与开发顺序

目录职责固定，避免参考 APK、研究产物和业务源码混放：

```text
app/              应用入口、导航、依赖装配
core/             数据、设计规范、媒体导入、连接、任务与渲染接口
feature/          相机、图库、胶片、LUT、导出、设置
native/           Vulkan、CPU 引擎、RAW 预览提取
assets/           卷标、暗盒、字体、预设及来源清单
tools/            资源整理与显式构建工具
docs/             产品、设计、协议、算法、适配与开发状态
research/         APK 分析和参考材料，原始大文件不入 Git
third_party/      固定版本的依赖源码与许可证
artifacts/        用户明确要求后生成的构建产物，不入 Git
```

核心接口保持职责清晰：

| 接口／数据 | 作用 |
|---|---|
| `CameraGateway`、`CameraCapabilities` | 相机发现、会话、功能能力、浏览、传输与控制 |
| `ImageImporter`、`SourceImage` | 导入 URI、提取内嵌 JPEG、记录来源及有效尺寸 |
| `EditRecipe`、`RenderEngine` | 胶片／双 LUT 配方、预览、导出、进度与取消 |
| `LutRepository` | 内置、官方、本地与分享导入的统一入口 |
| `BatchJob`、`ExportSettings` | 批次模式、逐张状态、统一画框及输出配置 |

配方、模型版本与批次状态保存在 Room；偏好保存在 DataStore。输出默认进入 `Pictures/LumixFilmMirror`，另支持用户选择文件夹。

实施顺序：

1. **基础与参考恢复**：建立 Git、目录、设计规范；整理三份 APK 的版本、协议和资源清单。
2. **传输与最小成片链路**：全部机型建立适配表，完成共同连接与传输路径，以及 JPEG／RAW 内嵌 JPEG 导入。
3. **影像引擎**：完成胶片模型移植、双 LUT、预览、批量配方和统一画框导出。
4. **正式交互**：接入暗盒选型、拍立得画廊、Palette 筛选及每批一次的显影揭晓。
5. **完整相机能力**：补齐遥控、定位、设置复制、电源和固件模块，持续更新机型矩阵。

源码按完整功能单元提交；上游版本与模型一起固定，升级作为独立改动。应用代码采用 GPLv3，模型、字体、LUT 和素材逐项保存来源与许可说明。

## 5. 验收清单与开发约束

以下是后续验收清单，**仅在你明确要求测试时运行**：

- 相机：各型号配对、浏览、传输、断线恢复，以及其实际支持的控制功能。
- 导入：JPEG、不同 RW2 内嵌预览、方向与尺寸、缺少预览、RAW＋JPEG 混合批次。
- 算法：与固定上游参考比较；确认 halation、柔光、颗粒、分块边界及预览／导出关系。
- 批量：逐张调整、首张统一、模式切换、一次动画、跳过、暂停、取消、部分失败与恢复。
- LUT：双槽顺序和强度、官方访问路径、本地与分享导入、离线使用及缓存清理。
- UI 与导出：400 ms 介绍触发、返回位置、全面屏手势、减少动态效果、全部旧画框和统一批量应用。

日常开发进行代码审阅、静态检查和 Git 差异检查。**不自动运行回归或冒烟测试，不因新增功能自动打包 APK。** 测试与打包分别由你的明确指令触发，开发状态如实区分已实现、已验证和待验证。

当前未进行功能测试、性能基准或 APK 打包；官方 LUT 直连条件和全部机型的实际兼容性仍需在对应开发阶段确认。
