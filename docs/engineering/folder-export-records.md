# 自选文件夹导出记录

2026-10-11：新增源码与工作台入口。未编译、运行、测试或打包，不作为 SAF 提供者兼容性、持久性或中断恢复已经通过的证据。

## 写入与恢复

每次文件夹 JPG 导出在创建目标前，先写应用私有 `files/folder-export-records/<UUID>.json`。记录包含版本、独立导出 ID、本次输入 ID／名称、请求文件名、所选 tree URI、文档 URI（初始为空）、编码文件字节数、开始时间与阶段。它不保存原始图片内容，不重新使用源文件名覆盖现有成片。

记录使用 [Android AtomicFile](https://developer.android.com/reference/android/util/AtomicFile) 的 startWrite／finishWrite／failWrite，并同步本地记录的文件描述符。AtomicFile 本身不提供并发保护，因此记录、图片编码／复制／提交、恢复读取及手动移除都共用现有 `JpegExportAccess.mutex`，不同 ViewModel 的 writer 也串行。文件版本 1 独立于现有 Room 数据库，未改变照片和传输队列的 schema。

| 阶段 | 保存时机 | 恢复后的说明 |
|---|---|---|
| PREPARED | 在调用提供者创建文档前 | 创建结果待核对；尚无已保存文档地址 |
| CREATED | 提供者返回新 URI，地址核对及记录写入完成后，开始复制之前 | 文档已登记，但可能只写入一部分或尚未记录完整结果 |
| COMMITTED | 本轮字节计数匹配、flush／关闭完成，进入不可取消提交段后 | 已记录完成写入；通过保存的 URI 打开核对 |

创建调用仍是现有 [DocumentsContract 文档创建](https://developer.android.com/reference/android/provider/DocumentsContract#createDocument(android.content.ContentResolver,%20android.net.Uri,%20java.lang.String,%20java.lang.String)) 对应的 DocumentFile createFile。提供者可能修改实际名称，恢复显示的是请求名称，打开使用实际返回的 URI。名称不作为所有权、存在或内容完整的证明。

目录和文件只在应用自己的单层记录目录内读写；符号链接、不认识的名字／版本／格式保留并显示说明。读取记录不扫描用户文件夹、不批量查询或认领同名文件，也不自动删除外部文档。重新启动／工作台恢复、导出结束和“刷新记录”均读取这些说明；已发布相册图片仍沿用自己的生命周期，未混入 SAF 记录。

## 取消与错误

本轮创建并成功登记的文档在提交前复制失败或取消，仍按现有行为尝试删除本次目标；仅删除成功后才移除私有说明。失败则保留 CREATED 记录。URI 异常或地址记录未写成，不自动删除该未登记文档，保留 PREPARED 说明以供核对。

复制、flush 和关闭完成之后，提交段先标记本轮结果不可删除，再保存 COMMITTED 并调用工作台成功回调。若完成记录保存失败，保留已经写完的文档，报“JPG 已写入，但完成记录未保存”；不计为普通确认成功，也不会在 catch 中删除。CREATED 记录可协助用户找到此结果。成功回调之后不删除成片；普通取消只结束后续项目。

本地 COMMITTED 仅说明应用完成了上述写入及记录步骤，不证明云盘已同步、不证明提供者实际落盘的持久性，也不证明文件后来仍存在或可解码。当前记录面板提供“打开核对”，权限失效、文件被用户移除或图片查看应用不可用时给出相应提示。没有依靠失败的查看操作把记录改为已删除。

## 工作台操作

最小浅／深色工作台增加“自选文件夹导出记录”面板，按创建时间倒序，每页 20 项。显示本张来源名称、请求文件名、时间和状态；有 URI 的记录可打开，无 URI 的记录提示在目标文件夹按名称和时间人工核对。

“移除记录”弹窗明确仅删除这一条应用私有说明，不删除图片、不把未知结果确认为成功。确认后检查本地记录及其备份／新写文件是否仍存在。操作与活跃导出互斥；失败保留说明，不自动清空全部历史。

## 剩余边界

- 外部提供者创建目标和本地保存返回 URI 之间无法组成同一事务。该时刻被终止可能留下 PREPARED 与实际文档；应用不按名称猜测和删除它。此窗口需要人工核对，不能宣称任意中断均已自动恢复。
- 文件夹日志本身不是导出执行器。后续 Room 8 [持久导出任务](export-queue.md) 记录请求和项目结果；两层记录各自保留，不自动继续写入 CREATED、不重新编码覆盖文档、不把任意历史 COMMITTED 加回当前请求成功计数。保存结果未知时先核对，明确重试仍产生新的独立文件。
- 旧版本在接入记录前创建的 SAF 文档无法追溯登记，仍由用户自行核对。
- 提供者修改 URI／权限、远端同步、实际尺寸与内容校验、大量历史读取和清理策略、整批持久配方／导出任务还需继续。未执行性能、杀进程或其他测试。
