## 当前用户流程

在相机菜单开启蓝牙配对 → 工作台“查找蓝牙相机” → 扫描结束后选择相机 → 按相机屏幕确认 → 读取 Wi-Fi 名称和密码 → 有已识别启动能力时点击“启动传输 Wi-Fi 并连接”，否则在相机上开启 Wi-Fi 后直接连接 → 系统网络确认 → 沿用 Wi-Fi 发现、身份握手、浏览和传输链路。

启动入口按实际发现的可写特征、通知特征与描述符显示，仍只是协议能力判断。保留“已在相机上开启 · 直接连接”；失败后需重新读取资料或使用普通 Wi-Fi 输入入口。不会因为读取资料就自动启动相机网络。

扫描最多 20 秒，在前台接收广播后由软件筛选 Panasonic 正常／配对状态，不连接睡眠、唤醒或远程开机状态。厂商数据只需包含实际读取的状态字节，不再因缺少六字节广播身份而丢弃。不能用广播名称或厂商 ID 作为身份认证；连接后还要读取已识别服务，Wi-Fi 链路仍检查 Panasonic 相机描述并执行正常相机确认。

扫描和 GATT 读取均可取消。普通资料读取在 Activity 停止后给旋转重建保留 500 ms，界面未回来就取消；成功、失败、超时与取消路径都关闭连接。用户开启的后续照片接收由前台服务持有 GATT，在等待期间订阅发送事件，结束时关闭；不因 Activity 重建而关闭，也不在启动恢复时自动重连。没有后台自动扫描。

新应用使用自己生成并保存的客户端 UUID，与现有 HTTP 握手共用；不读取旧应用种子、配对数据库或 privatekey 偏好。参考前缀保留协议格式，随机部分由新应用产生。名字固定为 16 个 ASCII 字节 `Lumix FilmMirror`，旧分支原样写入。

APS 二进制封装为 20 字节：长度前缀、数据、0xFF 填充；小端四字节词与挑战异或后按大端输出。挑战为零使用参考常数 -1875740628。参考 `m4426c` 的字符串 JADX 输出有变量重排和子串索引问题；当前只使用恰好 16 字节的名字，此时其零填充循环为零次，后三字节为 0xFF，与已恢复的 `m4427d` 二进制格式一致。这是源码推导，未执行参考编码器或对拍，不能扩大为任意长度名字已恢复。

密码按参考格式反向转换、跳过首字节、遇到 0xFF 截止，并按 Java trim 去掉末端空白／NUL。它是协议混淆格式，不把它当作密码加密存储。密码不进入 UI State、saved instance state、Room、DataStore、日志或生成的 `toString`；只在应用连接对象里临时持有，重新读取、断开、离开闲置工作台、Wi-Fi 连接结束时释放引用。暂存字节会清零，Java／Kotlin 字符串仍由运行时管理，不能承诺内存中的字符串已物理擦除。

## Android 接入

2026-10-13 针对用户 S5／Android 13 的空扫描报告，移除 `BLUETOOTH_SCAN` 的 `neverForLocation` 标记。按 [Android 蓝牙权限说明](https://developer.android.com/develop/connectivity/bluetooth/bt-permissions)，该标记可能过滤部分 BLE 广播；官方参考 APK 没有该标记。前台查找改为申请附近设备及精确定位权限（同时申请 coarse／fine），检查系统定位开关，但不调用位置 API 或读取位置；既有地址的 GATT 连接不额外要求扫描定位权限。BLE 硬件是可选项，无蓝牙时仍保留 Wi-Fi 入口。Wi-Fi 权限仍独立申请。此修改是兼容性修正，未证明该标记就是本次 S5 故障的实际原因；见 本次排查。

GATT 请求串行执行，读取回调立刻复制数据；Android 13+ 使用 [BluetoothGatt 新的带 value 写入接口](https://developer.android.com/reference/android/bluetooth/BluetoothGatt)，特征与描述符都走新版接口；旧版本走兼容接口和旧读取／通知回调。连接等待 30 秒、服务发现 20 秒、每次读写 20 秒；失败、拒绝或缺失特征给出重新配对／Wi-Fi 入口提示。超时仅转换本次等待的超时，保留外层取消。没有调用系统 `createBond`，是否需额外系统绑定流程仍待逐型号确认。

`e182ec40` 是参考应用的共享连接／模式特征，普通入口只写上面的固定值 3；发送入口只在收到相机对应通知后选择固定值 1 或 6，公开 API 不接收任意模式字节。它用于启动照片传输连接，不发送取景、拍摄、曝光、参数复制或电源指令。SoftAP 入口固定为直连，不上传路由器资料；另有普通 STA 入口只上传用户输入的路由器名称，见 同路由器连接。

订阅与写入等待各自回调，不在 Android 接受请求后就宣称相机完成了网络启动。当前没有恢复“Wi-Fi 就绪”通知的完整正向状态；实际成功仍由系统 Network、相机 HTTP 握手和浏览判断。等待 Wi-Fi 的过程中收到连接拒绝、STA 回复或空连接状态，会取消本次交接，释放网络请求并显示原因。单纯的 BLE 断开不能证明 Wi-Fi 失败或成功，进入交接后继续由 Wi-Fi 链路判断。

该操作没有自动撤销已启动的相机网络；用户取消会终止本应用等待、关闭 GATT 并释放自身网络请求，需要时可在相机上关闭 Wi-Fi。没有为了撤销而猜测共享模式特征的其他数值。

## 相机请求的发送模式启动

2026-10-11 补充源码。Wi-Fi 资料页在同时具有普通启动能力和两种发送事件能力时，提供“等待相机发送并连接”。用户先点击入口；重新读取资料、核对 SSID 并成功订阅四种通知后，界面提示在相机上开启拍后发送或选定文件发送。等待最长 90 秒，离开界面或点击取消会结束本应用等待；无需选择应用里的模式数字。

| 相机模式通知首字节 | 固定连接模式 | HTTP 预期 |
|---|---|---|
| 1 | 1：拍后发送 | `upload_bt` |
| 4 | 6：选定文件发送 | `transfer` |

映射依据是 `C0393g.onCharacteristicChanged`（样本行 639–685）和 `C0272a.f1067b/f1072g`；SoftAP 写入 1 后写当前发送模式的依据是 `C0393g.onCharacteristicWrite`（行 886–921）的后台分支。当前应用把该固定顺序作为用户显式启动操作，不移植参考应用的前后台检测、Wi-Fi 系统开关或私有偏好。

先订阅 Wi-Fi 选择、连接状态、图片和模式事件；只有相机通知 1／4 后才向 Wi-Fi 类型写固定 1，再向连接模式写对应固定 1／6，各步等待 GATT 成功回调。通知 2、图片通知 3、空事件、模式变化或请求重读资料 3 会结束交接；STA 回复依旧要求切换直连。发送启动的 GATT 断开也结束交接。取消／失败释放 GATT、密码引用及本次网络请求，不尝试猜测撤销命令。

HTTP 握手后在目录初始化之前检查相机实际 accessMode；不一致则关闭本次会话，不调用普通播放初始化或尝试其他模式。如果发现多个相机，不自动选中；保存本次请求的预期模式与所选 Network 的进程内关联，用户后续选择时再核对 HTTP。该情况下启动 GATT 在发现返回时关闭，不声称已完成单个相机的 HTTP 交接。连接完成后接收仍由用户点击单轮／后续入口开启，避免把连接与文件保存混为一个成功状态。

初次启动时，订阅之前已经发生的模式通知不会作为本次请求凭证；超时可重新发起或用手动 Wi-Fi 入口。已经识别的模式切换／资料更新事件可以生成进程内请求，再由用户开启重新握手，见 [发送更新流程](automatic-transfer.md#模式切换与资料更新)。更新入口重新读取资料，订阅之后核对最新模式通知；不要求相机重发已捕获的旧事件，不使用上次密码或旧 HTTP 会话。STA 发送另有独立入口，先等待相机模式，再发路由器名称、STA 类型 2 和对应模式 1／6；后续接收与更新仍保留 STA 路径，见 同路由器连接。更多通知与扩展事件仍需继续。
