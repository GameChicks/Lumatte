# 色彩推荐修正 · 2026-10-18

维护者指出三处问题：未下载 LUT 用创作者例图冒充当前照片预览；推荐页被上下纸色区域截断；彩照混入黑白 LUT。后续澄清：色彩推荐不需要黑白入口，也不应给黑白原图重复推荐黑白效果。本次按这个最终意图调整。

## 最终行为

- 色彩推荐仅有彩色推荐、自然、暖调、冷调。删除黑白按钮，旧保存的黑白选择归回彩色推荐。后端也过滤黑白方向，不靠前端隐藏实现。
- 黑白或几乎没有色彩的原图返回明确的 `inputProblem`，提示换彩照或手动选 LUT。官方路径在这一步返回，不请求远程候选。
- 本地与官方推荐都基于当前照片的小图采样。官方创作者例图只用于初筛，不能成为推荐卡片：最多获取五款候选 grid17 LUT 临时试用，实际采样评估通过才进入结果。下载/预览失败不回退到例图。
- 临时 LUT 保存在处理器的八项内存缓存，不写入持久 LUT 库；正式选用仍走原下载导入流程。原图不上传；只有现有 HTTPS 目录与下载请求。应用结束后内存缓存释放。
- 推荐页背景由根绘制层连续覆盖状态栏、内容、按钮背后与手势区；内容继续遵守 `safeDrawing`，不隐藏系统返回手势。筛选开关默认收起，拍立得宽由视口 53% 改为 68%，最大 312dp。上下纸色割裂区域撤除。

## 算法与预算

这是有边界的色彩启发式，不是题材识别或全库最佳审美判断。

1. 输入小图按约 4096 点目标取样，计算 RGB 最大最小通道差与有效彩色占比。差值大于 .035 且最大通道大于 20/255 算有效彩色点；有效彩色点占比低于 2%、平均通道差同时低于 .012 时停止色彩推荐。这个条件尽量保留有少量真实颜色的低饱和照片，实际阈值尚未做照片集校准。
2. LUT 特征增加等亮度彩色探针的色度响应。去掉输出色度的固定偏置后计算离散程度，能排除普通黑白及仅加固定色调的单色 LUT；响应低于 .12 不参与色彩推荐。特征缓存改为 v2，不沿用旧三字段缓存。
3. 在原有最多 256 款本地候选、每方向六个特征初筛的限制内，用当前照片实际采样排序。当前仅三个方向，最多 18 个去重前试套候选；通用上限仍为 24。
4. 结合实际输出再排除明显去色结果：输入平均色度大于 .045 时，输出低于 `.025` 或输入的 18% 中较大值，不进入彩色推荐。暖调需实际红蓝差增量大于 .006，冷调小于 -.006；自然方向限制偏色并保留一定原有色度。
5. 新增裁切超过 18% 或亮度反差保留低于 18% 的候选剔除；排序继续惩罚裁切，并增加低反差惩罚。新增裁切超过 1% 的可用候选保留原强度提醒。不用不合适的结果凑满五张。
6. 官方仍最多读取 96 条元数据、12 张小例图初筛，随后最多五个真实 LUT 顺序读取，共 30 秒附加获取预算，取消会传播。它不是整个官方库的真实试套排序。临时文件采用既有 ZIP/HTTPS 校验，严格 UTF-8、最多 4MiB 的 cube 文本、无一维表且三维表为 grid17。
