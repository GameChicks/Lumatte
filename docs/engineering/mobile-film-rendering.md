# 移动胶片 GLES／CPU 图像后端（2026-10-11）

> 2026-10-14 更新：默认空间算法已经改为 空间效果 v2，同时修复 GLES 着色器保留字。NDK 两种 ABI、着色器和 Kotlin 源码编译已通过；没有照片渲染、设备/性能测试或本轮 APK。下文是 2026-10-11 的实现记录，其中旧亮部阈值、强度下限、空心光晕和旧黑柔混合参数不再是默认源码行为。CPU 后备的四线程与导出诊断优化见后续代码和 v2 文档。

默认源码执行路径现为 `FilmEngine → MobileFilmRenderer → lfm_mobile_film`，优先 GLES 3 图块扫描；GPU 能力／驱动失败时，writer 重新解码未处理的 JPEG，再由同模型原生 CPU 重做。PhotoProcessor 的预览、构图预览和导出均接入此路径。使用已生产的 spektrafilm 三阶段表，统一曝光、Halation、四档黑柔和各张独立种子继续使用既有配方。没有执行 CMake／Gradle、JNI、照片渲染、设备验证、测试或基准；不能称为运行通过或性能达标。

GPU 后备仅处理专属 `MobileFilmGpuFailure`，包括 GL／EGL 报告的资源分配或驱动错误。库缺失、模型错误、CPU 计算错误、主机分配抛出的内存不足和取消保留原错误，不进入循环重试。GPU 失败在串行 worker 内立即禁用当前进程的后续 GPU 尝试，包括已经排队但尚未启动的请求；重启进程才能重新尝试。这里是源码行为，尚无实际自动后备运行证据。

## GLES 图块与资源

独立 EGL pbuffer／ES 3 上下文只属于共享影像 worker，不共享页面 GL 对象。初始化检查真实 GLES 版本、fragment highp 浮点精度、纹理单元、3D 纹理及 viewport 限制。响应／显影／扫描表使用 RGB32F 3D 纹理，空间场使用 RGB32F 2D 纹理，以 `texelFetch` 手工插值；输出附件使用 RGBA8，不依赖浮点颜色附件或 float32 硬件线性过滤。格式及像素传输依据 [OpenGL ES 3.0.6 规范](https://registry.khronos.org/OpenGL/specs/es/3.0/es_spec_3.0.pdf)，上下文依据 [EGL 1.4 规范](https://registry.khronos.org/EGL/specs/eglspec.1.4.pdf)；设备上的分配、着色器编译和 FBO 状态仍需运行确认。

逻辑图块边长最多 1024，末端按实际宽高绘制。两张 RGBA8 图块纹理各最多 4 MiB，CPU 回读缓冲最多 4 MiB；不是驱动实际分配或整个应用的内存上限。输入以 stride／row-length 上传，回读在检查错误、数值哨兵和取消后逐行写入本次私有位图。所有空间场先由未改写的输入完成，图块不从邻块结果取样，颗粒使用完整源图坐标；不建立整张 GPU 图像或密度平面。当前宽散射使用有界场，未加入全分辨率短邻域细化。

GPU 缓存只保留当前胶卷三阶段表与固定图块纹理。更换模型先清空缓存标识，三次表上传全部成功才登记，避免中途取消留下错误标识。空间场每张更新，空场用零值 1×1 纹理。CPU 和 GLSL 遵循相同阶段、参数、种子规则；CPU 的 double 坐标与 GLSL float、log／pow 和 RGBA8 量化可能不同，不宣称逐像素相等。

GPU 任一图块失败，先等待 GL 工作排空、解除位图锁，再销毁本次上下文资源；writer 丢弃整张半成品，按原尺寸／方向重新解码不可变 JPEG，恢复位图清理归属后调用 CPU。重新开始不改配方、照片种子、导出尺寸或共享画框，画框与发布只在完整处理后执行。取消只丢弃结果，不触发 CPU；上下文清理仅销毁本后端对象，不终止也服务 Android UI 的默认 EGL display。

## 数据与处理顺序

任务按所选胶卷加载经哈希校验的 response／development／scan 表，复制约 1.61 MiB 数值表到原生任务，Kotlin 缓存不被修改。另读取 manifest 的原始颗粒、Halation 与胶片幅面参考参数。JNI 校验三阶段尺寸、颜色域和效果参数，接受由 JPEG writer 创建的可写、软件 ARGB_8888 sRGB 位图，按实际 stride 访问 RGBA 字节。

顺序：镜头线性 RGB 黑柔 → 编码 sRGB 感光响应表 → 胶卷响应域 Halation → 单一 `2^EV` → log10 曝光／显影表 → 密度颗粒 → 印相／反转片直扫表 → 8 位编码 sRGB → 既有共享画框和 JPEG。逐像素 DIR 已在显影表内，运行时不再重复执行；空间 DIR 仍省略。

没有开启黑柔时，直接将输入编码 sRGB 查响应表，省去逐像素的解码／再编码。开启黑柔时，CPU 用 256 项查表解码、GLSL 用分段 sRGB 公式，再在镜头线性域混合并编码回响应表的输入域；此域在 0～1 端点夹取，不能补回 JPEG 已裁切的高光。

## 有界空间场

空间分析图两个方向均不超过 512 像素，长边尽量占满上限。每个源像素恰好落入一个分析单元，先从尚未修改的原图生产完整空间场，再逐行就地提交颜色结果。原生路径不建立全分辨率 RGB／密度 float 平面，也不复制另一份整图 RGBA。源图解码、方向处理和画框仍需要全分辨率位图，不能将空间场上限说成整个应用内存上限。

黑柔沿用本项目线性镜头散射的三个尺度：0.75 的核心、3.5 的高光晕、10 的宽散射，三档 strength 为 0.125／0.25／0.5，内部核心混合为 strength × 0.15，高光晕／宽散射为 strength × 0.22／0.10。高光提取改为在源像素中先阈值，再面积平均，减少小灯先被平均后消失的情况；因此不宣称与旧完整参考路径逐像素一致。各尺度结果累计成一份镜头场，临时滤波平面按阶段释放。

Halation 在镜头处理后的源像素上提取亮部，再将其胶卷响应面积平均；使用整体线性亮度峰值的 0.55 与 0.06 下限产生平滑掩码，先提取再降采样。输出由 0.7 的主散射与 0.3 的宽尾减去窄核心，保留正的周围光晕；不启用独立的图像全局高亮 boost。关闭时不生产该场，也不遗留 boost。

为用户要求的可辨识艺术效果，内部候选强度为胶卷原始反射强度 × 2，并设 RGB 下限 0.10／0.025／0.003；半径来自胶卷微米参考值与幅面尺度，主半径至少 1.2 个分析像素，尾半径为其 2.25 倍。高斯 sigma 上限 24 个分析像素，核截断到 3 sigma，边缘延拓。**这不是实体滤镜或胶片防光晕层的标定**，也没有夜景照片证据证明开关差异已经满足要求。纯暗图／无亮部图自然可能没有光晕；分析分辨率和核截断仍可能损失细小高频形态。

## 密度颗粒近似

颗粒在 CMY 密度域、印相／扫描前加入，不在成片 RGB 上撒统一噪点。沿用源模型的粒子面积、通道粒子比例、密度底和 uniformity，用胶片幅面／实际处理像素计算每像素面积。由其 Poisson／binomial 粒子结构得到方差项 `Dmax² × p × (1 − p × uniformity) / N`，保留随密度和分辨率变化的幅度。

随机分布采用三份均匀数之和的近似零均值／单位方差噪声，双线性相关场按权重能量归一化，并有少量跨通道共享分量。这省略源模型的精确 Poisson／binomial 抽样、各子层／染料云和微结构，不宣称分布、颗粒形态或色彩噪声与桌面相等；仍需后续核对。胶片颗粒强度不新增专业 UI 控件。

种子使用该张完整 64 位种子，噪声坐标映射到有效源图，逐行处理不重新播种。首张继承只共享参数，不复制首张噪声。预览的采样面积与最终图不同，幅度和像素噪声不保证逐像素相同。

## 取消、缓存与参考构建

任务由原生单线程队列执行，原子取消标记在分析行、滤波行、CPU 每 256 个输出像素、GPU 上传／绘制／回读边界及回写行检查。单次驱动调用仍不能在内部中断。Kotlin 取消等待原生返回、GL 排空、位图解锁与任务释放后再完成，writer 才能回收位图；部分就地结果不会发布或用作重试输入。结果后仍沿用既有 JPEG 编码／相册与 SAF 发布记录。

PhotoProcessor 和其 writer 共享一份模型库。`clearProcessingCaches()` 等待预览门、排队等待原生工作结束，在所属 worker 销毁空闲 EGL／GL 资源，再丢弃模型和位图缓存引用；未使用原生库时不为清理而加载。其他新任务可以随后排入，清理不是强制进程峰值限制。`filmBackend()` 返回配置的 `MOBILE_GLES3_WITH_CPU_FALLBACK`，不初始化 GPU，也不是当前设备实际执行后端、速度或可用性证明；不向用户增加引擎选择。

2026-10-17 开源目录整理：不再被产品调用的 C++／Vulkan 参考引擎、Android `ReferenceFilmEngine`、参考构建开关和桌面资源已移出源码树。普通移动构建保留现有 GLES / CPU 产品链路；LibRaw 与运行模型的来源和许可仍保留。
