## 交叉核实与修改

### 首次配对不能复用重连模式

修改前 `ConnectionGatt.startTransferWifi()` 无论相机是否在 pairing 广播状态都写模式 3。官方恢复源码 `p026D4/C0272a.java` 的 `f1071f={5}` 与 `f1069d={3}`，`p033E4/C0393g.java` 的 `onCharacteristicWrite`（约 971–1013 行）在首次分支 Wi-Fi 类型写入完成后写 `f1071f`，普通分支写 `f1069d`。这与用户日志一致。

现在普通直连入口依据所选相机广播的 `camera.pairing`：pairing 状态使用固定 5，normal 状态使用固定 3。不接收调用方任意模式字节；未增加取景、拍摄、录像或电源功能。广播状态只是选择请求路径，不是配对成功凭证。配对是否被相机接受仍由 Wi-Fi 和 HTTP 确认决定。

Wi-Fi 类型仍为官方首次分支的固定 SoftAP 1。第三方日志虽然文字标注 `sta`，但没有给 cmd 11 的实际字节，不能由标签推断需要发送 ASCII `sta`、类型 2 或上传路由器资料。原有路由器与相机请求的发送模式不在此次指令修改范围。

### 系统确认不能被当作用户放弃连接

`MainActivity.onStop()` 调用 `CameraController.detachUi()`。修改前，只要没有可见 Activity 且处于蓝牙/网络选择流程，超过 500 ms 就取消 `cameraJob`，使 GATT 和网络请求被释放。日志中成功连接包含多个明显超过 500 ms 的后台间隔，因此这个生命周期条件与系统确认过程不兼容。

新增进程内、单次操作的 `withBluetoothConnectionLifetime`，用于已选择相机的读取/首次直连，以及现有普通/发送直连入口。操作期间临时停止 idle release，允许系统蓝牙或 Wi-Fi 确认页面切换；整次操作最多 5 分钟，结束恢复原有释放策略。用户点击取消仍即时取消等待并释放资源。扫描不受该保护，不增加自动后台扫描、自动重连或后台服务；Android 杀进程仍会结束操作。路由器高级入口的现有策略未在此修改。

### 系统 Wi-Fi 等待时间

原 `requestNetwork` 系统超时为 30 秒，外围包括地址准备的超时为 45 秒，均短于日志中约 63 秒的成功确认。现在分别为 90 秒和 105 秒，继续等待实际 Wi-Fi capability 和 IP 地址，继续固定使用返回的 Network，不改变全应用网络路由。超时或取消释放本应用的网络请求，不无限等待或反复请求。

## 未采纳的猜测

用户进一步指出第三方连接时相机显示“正接受远程控制”，并询问它是否因为采用遥控握手才成功。需要区分通用访问会话与具体拍摄指令：日志使用的 `accctrl/req_acc` 在官方 `C3472a.java`（约 441–473 行）同样用于授权，返回的 `remote` 字段不能独立证明已发送取景或快门命令。可理解为共享遥控/浏览连接入口，不应为了排除产品中的遥控功能而绕过这段正常授权。

本应用普通文件浏览在 HTTP 授权后由 `LumixCameraSession.prepareBrowsing()` 执行固定 `camcmd/playmode`，接着准备 RAW 资源并进行 SOAP 目录读取；`upload_bt` / `transfer` 使用各自指定目录而不切播放模式。用户的第三方日志在首次授权成功后就断开，没有记录 `playmode` 或照片目录，因此不能据此确认它完成了与官方相同的浏览初始化，也不能从显示文字推断我们应加入实时取景、快门或录像功能。该提示的具体屏幕差异仍需对应运行日志，不能宣称所有机型都会显示同样的字样。

- HTTP 标识没有改成第三方日志中的字符串。第三方的 HTTP 无连字符形式与本应用不同，但官方 `C0941p.m4405y` 的 HTTP 标识本身带连字符，现有本应用形式有官方依据；BLE 则是同一自有 UUID 的 16 字节表示。不复制第三方配对身份、不迁移或读取旧应用 privatekey。
- 旧身份协议顺序已是标识 → 名称 → SSID → challenge → password，与本次日志一致。当前密码反混淆在该全零/结束填充的形式下得到空密码，空密码走开放网络；没有为了这个样本增加解析失败后一律开放网络的降级。
- 成功日志注册了更多通知，但不能据此证明 GPS、遥控或其他扩展通知是连接必需。本次不把无关命令全部移植。
- 日志没有系统 bond 事件，不能判断是否需要主动 `createBond`，本次未增加。

## 下一次诊断的记录

`LFMBle` 增加 `connectionFlow=s5-pair-v2`、legacy/APS 分支、首次/重连启动类型、协议操作 UUID 和成功状态。`LFMWifi` 记录等待限额、网络准备完成/不可用的耗时；`LFMCamera` 记录 HTTP 协议分支、尝试次数和已识别状态词。没有记录 Wi-Fi 密码、原始响应、challenge、手机身份、相机地址、SSID 或会话 ID。
