## 想法一：根据照片推荐 LUT

### 用户想法

在 LUT 页面取得创作者上传的例图，对例图取色；进一步识别 LUT 本身的色彩倾向，以及可能适合的色彩场景。用户导入照片后，结合照片特征推荐相应 LUT。

推荐不必只有一个答案。可以分别提供自然、温暖复古、冷调电影感等方向，保留用户自主选择与现有双 LUT 编辑能力。

### 建议的判断依据

**创作者例图与说明**：主色、颜色占比、明暗分布、冷暖、饱和度，结合创作者介绍、官方分类及建议输入照片风格。例图可以提供线索，但也受到拍摄内容、照明、曝光和其他后期处理影响。例如例图中绿色很多，不能直接证明 LUT 增强绿色或适合全部风景照片。

**LUT 的实际变换特征**：在明确输入色彩空间和编码的前提下，将标准灰阶、肤色范围、天空蓝、植被绿等颜色输入 LUT，记录输出差异。形成可缓存的特征，例如：

- 阴影、中间调和高光的冷暖变化。
- 不同色相的偏移、饱和度增减及颜色之间的分离。
- 灰阶中性保持情况、对比度与高光压缩趋势。
- 肤色变化、暗部损失、裁切或异常颜色的风险线索。

这种分析描述数学变换的行为；“适合人像”“适合夜景”等仍需结合照片和实际效果判断。

**用户照片及真实效果预览**：分析照片的颜色、曝光和动态分布；需要时增加人像、自然、建筑、夜景等场景识别。先筛选输入兼容的候选，再用缩略图实际套用，评估结果并排序。

场景识别与审美判断是不同问题。大量绿色可能来自植被，也可能来自舞台灯光；单纯颜色分析不能可靠代替内容识别。照片需求还应结合用户选择的风格方向。

### 拟议流程

创作者资料与例图 → LUT 输入兼容性检查 → LUT 特征分析 → 用户照片分析 → 候选缩略图试套 → 分组推荐与理由 → 用户确认。

推荐理由应与可观察的效果一致，例如“降低植被饱和度、增强暖色建筑，同时保留天空层次”。不要显示缺乏依据的精确适合度百分比，也不宣称存在唯一最好的 LUT。

### 未来获准启动后的候选阶段

1. **特征基础**：明确 LUT 的输入约定，生成颜色变换特征；按文件内容哈希、输入约定及算法版本缓存，区分例图来源。
2. **简单推荐**：以本地颜色和曝光统计筛选候选，缩略图试套后展示几款不同方向及对应理由。
3. **质量完善**：按需要加入内容识别、用户偏好、建议强度和更可靠的效果评分；不预先确定必须使用大型 AI 或云端服务。
4. **后续扩展**：双 LUT 组合推荐另行评估。组合数量、顺序和两个强度会扩大搜索空间，不宜在第一版无界穷举。

以上是讨论用阶段划分，没有启动时间、工期或资源承诺。

## 想法二：根据厂家资料扩充胶卷模拟

### 用户想法

借鉴 spektrafilm 的技术原理，使用柯达、富士、乐凯及其他厂家的官方胶卷资料和冲洗数据，复刻更多胶卷的影调、色彩与质感，并探索不同冲洗条件。

### 技术依据与数据需求

spektrafilm 以厂家公开的测量资料建立感光、显影、染料密度、印相和扫描模型。扩充胶卷可沿用这种思路，但不同资料的完整程度并不相同。

| 数据 | 主要用途 | 缺失时的影响 |
|---|---|---|
| 光谱感光曲线 | 建立不同波长对感光层的响应 | 对照明、肤色和特殊光源的模拟依据不足 |
| 曝光—密度曲线 | 建立暗部、反差、高光肩部与宽容度 | 难以可靠还原不同曝光下的影调 |
| 染料吸收、片基与最低密度 | 建立色彩串扰、负片底色及后续印相 / 扫描 | 需要近似、拟合或补充测量 |
| 颗粒、清晰度、散射与光晕资料 | 建立质感及空间特征 | 不能仅凭 ISO 数字推断真实颗粒或光晕 |
| 冲洗条件与对应测量 | 建立药液、时间、温度等对响应的影响 | 只有冲洗时长不能准确模拟迫冲 / 减感 |
| 印相 / 扫描条件与对照样片 | 固定输出目标并校准模型 | 无法判断偏差来自胶卷、冲洗还是扫描 |

黑白卷应单独考虑银密度、光谱响应、显影液和冲洗条件，不以彩色模型去饱和替代真实黑白胶卷建模。

### 数据充足程度与表述

未来可按证据区分三种来源：

1. **厂家资料建立并有实拍校准的模型**：保留具体版本、测量条件与来源。
2. **资料不完整、由受控实拍补充的模型**：明确哪些参数来自资料、哪些来自测量或拟合。
3. **只有少量样片的风格近似**：按艺术风格标注，不宣称为完整物理复刻。

本次讨论确认 Kodak、Fujifilm 有可用的公开技术资料实例。乐凯及其他厂家仍需逐型号检索；尚未确认足够完整、可直接建模的乐凯官方曲线集，不能据此断言其资料不存在。

### 拟议建模流程

选择具体型号与版本 → 收集资料、来源及冲洗条件 → 曲线数字化与一致性检查 → 建立 profile → 受控曝光 / 灰阶 / 色卡实拍校准 → 生成移动端数据包 → 经授权进行 Android 效果与性能核对。

优先考虑电脑端完成建模、拟合和数据生产，再沿用本项目分阶段移动处理架构。新增胶卷不是简单复制名称或给既有模型换标签；数据包格式、精度、空间效果与移动端成本仍需评估。

有关既有路线的背景见 胶片引擎说明与[移动分阶段后端](../engineering/mobile-film-rendering.md)。这些文档中的历史状态不替代后续实际验证记录。

### 冲洗模拟的边界

“胶卷＋冲洗条件＋扫描 / 印相方式”应作为明确的输出目标。同款胶卷在不同流程下可能呈现不同结果。

迫冲 / 减感不能只用曝光滑杆代替：需要考虑对应密度曲线、对比度、色彩平衡和颗粒变化。只有温度、时间或药液名称时，应记录未知参数，不能凭这些字段宣称已经准确还原。

厂家曲线也可能只代表特定条件和典型样本；耦合、染料、空间结构等数据常需补充或近似。最终观感应以条件明确的实拍对照校准。

### 未来获准启动后的候选阶段

1. **资料清单**：先列候选型号、官方数据完整度、资料版本及来源记录，不预先承诺品牌数量。
2. **单款试点**：选一款资料充足的胶卷，明确标准冲洗与输出条件，完成模型和受控对照。
3. **移动端接入**：评估现有分阶段表示能否承载新增模型，记录近似及与参考模型的差异。
4. **逐款扩展**：按证据和实际效果再加入更多彩色 / 黑白卷；冲洗条件变体独立评估。

### 待定问题与验证需求

- 首款扩展目标是什么？先彩色还是黑白？优先乐凯还是资料更完整的其他型号？
- 是否具备可追溯的官方资料、实物胶卷、受控拍摄及固定冲扫条件？
- 需要复刻胶片直扫、光学印相，还是某种具体扫描风格？
- 不完整参数采用何种近似，怎样在元数据中区分测量、拟合和艺术调整？
- 新 profile 的来源、署名、许可和版本如何记录？
- 未来经用户授权后，需比较灰阶、多种曝光、肤色、植被、天空及不同照明；再评估手机速度、内存、GPU / CPU 差异和预览 / 导出一致性。

当前产品继续以 JPEG 或 RAW 内嵌 JPEG 为输入，不因这个方向扩大为传感器 RAW 显影。已经裁切的高光和原始光谱信息无法完整恢复，不能承诺任意输入、任意冲洗条件下与实体胶卷百分之百一致。
