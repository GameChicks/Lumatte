# 已有 Wi-Fi 网络选择

2026-10-11：源码及工作台对话框接入，未编译、运行、测试、连接相机或打包。

## 入口与选择

- “已连 Wi-Fi · 查找相机”：读取当前系统可见的 Wi-Fi，多个时由用户选择，再在该网络发现相机。
- 同路由器普通／发送／发送更新：先校验输入名称，选择手机已有的目标 Wi-Fi，随后才进行蓝牙身份／Wi-Fi 启动写入。取消选择没有启动本次蓝牙操作。
- 普通重新连接：已有保留连接时继续使用它；已释放时按同样方式选择网络，仍按原 UDN（缺少时为原描述地址与型号）找回相机，握手后再次核对身份。

单个网络保持直接使用；多个网络显示选择对话框，不把默认网络、列表第一项或旧索引作为自动选择。选项以本机 IPv4 地址及当前系统默认标记区分，不读取 SSID、密码或 BSSID，不新增权限，也不把用户输入的路由器名称当作已证实的系统 SSID。名称仍需在系统设置核对。

使用现有 `ConnectivityManager` 接口读取系统当前可见网络；只包含 Wi-Fi 且排除 VPN Transport。`CameraWifiNetwork` 保存当前 `Network` 对象、本机 IPv4 和默认标记，handle 仅为进程内列表键，不显示给用户或持久化。地址是手机接口地址，不是相机地址，不推导路由器密码或可达性。

依据：[ConnectivityManager](https://developer.android.com/reference/android/net/ConnectivityManager#getAllNetworks())、[LinkProperties](https://developer.android.com/reference/android/net/LinkProperties#getLinkAddresses())、[Network](https://developer.android.com/reference/android/net/Network#getNetworkHandle())。这些快照不是持续的在线证明，也不能证明厂家系统提供并行 Wi-Fi、输入 SSID 匹配或相机可访问。

## 生命周期与绑定

选择请求使用本次随机 ID，控制器持有可取消的等待及当前选项。对话框挂在工作台根层，照片列表／相机面板滚动及重建不会因为列表项未加载而藏住等待。刷新只更新同一请求的选项，不启动另一轮连接；旧请求 ID、未知 key 和重复回答不继续另一项操作。刷新后即使剩一个网络，已显示的对话框仍等待明确选择。无网络时允许刷新或取消，不改用蜂窝网络。

回答选择时及等待恢复后检查所选 Network 仍为当前 Wi-Fi。离开界面沿用 500 ms 重新附着窗口，然后取消选择等待；Activity 重新创建仍由应用控制器持有同一请求。取消、断线或异常在 finally 中释放等待并移除该对话框；不会自动保存选择、重连或继续 Room 队列。

随后保留该 Network 的应用请求或观察。若已经持有同一请求创建的 Wi-Fi，继续保留，不关闭该请求再尝试观察；不同网络先创建新观察再释放旧应用引用。系统现有连接不会被应用主动断开，应用自己的临时请求仍按既有关闭语义释放。

SSDP、地址定点发现及 HTTP 都使用固定的 Network。发现结果的选择检查它仍属于当前绑定网络且在线；错误或已断开的旧结果要求重新查找。网络断开沿用原有中断／暂停流程，不静默搜索其他 Network。模式和原相机身份检查仍在目录初始化前，网络选择本身不是相机身份认证。
