# 0.2.1 连接与首页复查 · 2026-10-17

依据维护者提供的 `Screenrecording_20261017_182930.mp4`（3.73 秒）及 `Screenshot_20261017_183053.jpg`，并按请求把现有 0.2.1 APK 安装到 D: 的 API 35 模拟器。没有用编译结果代替界面检查。

## 已定位并修改的源码

- 扫描中点连接：UI 允许选择，CameraController 也已有停止扫描并启动连接的通路，但 WorkspaceViewModel 的 `withCamera` 使用包含 cameraBusy 的总忙碌状态，导致点击在 ViewModel 被直接丢弃。拆出 localBusy，只允许回答当前扫描；其他握手、传输、导入、导出、恢复与存储故障仍阻止新连接。选机后立即显示 CONNECTING 与已选机型，再停止扫描，避免显示仍在查找而没有反馈。
- 卡片上下翻动：原先新内容入场方向与手指运动同向、旧内容退场反向。现记录本次实际手势方向，让旧内容跟手退场、新内容从另一侧入场；新增/返回按钮也设置对应方向。
- 排版：移除新增和切机按钮的右侧悬浮叠放。主卡统一 24dp 内边距，新增/浏览相册采用相同 16sp 操作字号和按钮内距；型号与 Lumix 根据实际可见字形左侧留白作光学对齐。多机导航有独立底行，卡片留出高度，随系统字号增长。

## 当前证据

旧 0.2.1 已在模拟器打开主页、相机连接和设置页，取得截图和 UI 层级，并检查 100% / 130% 系统字号。用户录屏已按 8fps 拆帧，核对正常/新增/删除状态与转场。已连接 S5 卡片的依据是维护者截图；模拟器没有真实 S5，不伪造配对成功或连接状态。

修改后 app Kotlin 编译通过，`BluetoothSelectionGateTest` 3 项 JVM 测试通过：扫描 busy 时可选机；其他握手/传输不允许并行；照片任务/恢复/存储故障不能被绕过。

这次安装的仍是现有 APK。上述源码修改尚未重新生成并装入 APK，因此没有宣称修复后完整视觉验收通过；真实蓝牙扫描发现后的系统握手仍需设备验证。后续模拟器安装新代码需要相应调试包授权，交付包和附件放 `dist/`。
